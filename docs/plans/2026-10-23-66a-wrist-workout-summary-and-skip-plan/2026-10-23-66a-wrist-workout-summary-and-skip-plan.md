## Goal and acceptance

Decisions (lead): (1) **the summary shows three lines: Time, Sets (or Efforts), and Avg HR** (only when the watch recorded heart rate), and a Done button; it appears after the effort question, only for a workout that was completed with at least one logged effort, and only if you were in the app while it ended. (2) **Skip is allowed on the watch only**: a small "Skip" under Confirm. Skipping records NOTHING (it is not an answer), so the phone's own question still appears on the phone's summary and the first real answer still wins. The phone's question keeps requiring an answer.

| What you do | Now | After 66a |
|---|---|---|
| End Session -> Finish Workout?, the phone asks for an effort rating | the question fills the watch; the only way out is an answer | same question, plus a small "Skip" under Confirm; Skip closes the question without recording anything |
| Answer (or skip) | back to the start screen | a "Workout done" screen: `Time 42:10`, `Sets 12`, `Avg HR 128 bpm`, then Done -> start screen |
| End a workout with no heart rate recorded (access refused) | n/a | no Avg HR line |
| End a workout where only runs/rows were logged | n/a | the count line reads "Efforts 2" (a mix, or no sets) instead of "Sets" |
| End a workout with nothing logged, or cancel an empty Free workout | back to start | back to start (no summary) |
| The phone ends the workout while the watch app is open | back to start | the same summary (any completion you see happen) |
| Relaunch the app after a workout ended while it was closed | start screen | start screen (the summary is for a workout you saw end) |
| Skip, then force-quit and reopen the watch app | n/a | the question comes back once (the skip is remembered only while the app runs) |
| A new workout starts (from the phone) while the summary is up | n/a | the summary gives way to the new workout |

How to SEE it (owner): on a watch or the watch simulator, start a Free workout, log a set, End Session, Finish. If the phone's setting asks for an effort rating you see the question first (Skip is under Confirm); then the summary. With the setting off you go straight to the summary.

Not in this plan: the phone's summary heart rate (66b); a Skip on the phone; saving a skipped state across relaunch; a summary for runs' distance/pace; the Dart twin.

## Facts from the scout (`.work/crew/2026-10-23-66/scout-finish.md`; spot-checked by the lead against `WatchEffortRating.swift` and `ContentView.swift`)

- Finish: `WatchMenuView.finishRow` -> `state.finish()` -> `WatchEffortRatingState.end()` -> `engine.finishSession()` (`transitionTo(status: completed)`), then `noteOwedPrompt` when a rating is owed. The shell root `ContentView.body` picks the surface in the order: `host.rating.isPromptOwed` (the question) -> rest -> logging (active session with exercises) -> `WatchStartView`.
- The question is `WatchEffortRatingView` (`#if os(watchOS)`); its state owns the owed list `prompts` (durable rows `prompt-<sessionId>`, append-only store); `owedSessionIds` = prompts whose session has no rating; `isPromptOwed` = `promptSessionId != nil`. A guard test (`WatchEffortRatingTests` ~l.839, `banned = ["skip", "dismiss", "cancel", "close", "later", "not now"]`) fails if such a name appears in the state or view files: it encodes the earlier rule "the only way out is an answer" and is amended by D-3 on purpose.
- Average HR already exists: `WatchSensorSummaries.heartRate(_:from:through:excluding:)` returns `WatchHeartRateSummary(averageBpm:maximumBpm:)` over a window, nil without readings; `sessionEndEvent` already uses it for the whole session. The session row carries `startedAt`; the completed row's `recordedAt` is the end instant (phone-sent completion: the snapshot's `sentAt`, D-120). No wrist helper for paused time: Time is end minus start.
- The host re-reads on every session change through `$revision`'s sink in `WatchAppHost.init` (which already runs `restPings.arm()`, `workout.refresh`, `sensors.refresh`), and bumps `revision` from `rating.objectWillChange` through a Combine sink: the summary state follows the same pattern.

## Decision Ledger

- D-1 New file `watch/watchos/Sources/WatchSessionEngine/WatchWorkoutSummary.swift` (package, not `#if os`): `public enum WatchWorkoutSummaryCopy { title = "Workout done"; time = "Time"; sets = "Sets"; efforts = "Efforts"; avgHeartRate = "Avg HR"; done = "Done"; bpm = "bpm" }`; `public struct WatchSummaryRow: Equatable { label: String; value: String }`; `public struct WatchWorkoutSummary: Equatable { sessionId; startedAt; endedAt; effortCount: Int; allSets: Bool; averageBpm: Int? ; rows: [WatchSummaryRow] }` where `rows` = Time (`durationText`), `Sets`/`Efforts` = count (label `sets` iff `allSets`, else `efforts`), and `Avg HR` = `"<n> bpm"` only when `averageBpm != nil`. `static func durationText(_ seconds: Int) -> String`: `m:ss` under an hour (59 -> `0:59`, 754 -> `12:34`), `h:mm:ss` from an hour (3725 -> `1:02:05`); negative clamps to 0.
- D-2 Same file: `public final class WatchWorkoutSummaryState: ObservableObject` (`init(engine: WatchSessionEngine)`): `@Published public private(set) var pending: WatchWorkoutSummary?`; `private var activeSeenId: String?`; `public func note(_ session: WatchSessionRecord?)` called by the host on every session change: when the session is `active`, remember its id in `activeSeenId` and, when `pending` belongs to another session, take `pending` away (a new workout gives way); when the session is `completed` AND `session.sessionId == activeSeenId` (this process saw it active) AND `pending?.sessionId != session.sessionId` AND the session has at least one effort entry (`WatchObservationKind.efforts.contains(entry.kind)`, entries of THIS session) -> build the summary: `startedAt = session.startedAt`, `endedAt = session.recordedAt`, `effortCount`, `allSets` (every counted effort has kind `set`), `averageBpm` = `WatchSensorSummaries.heartRate(engine.sensorSamples, from: startedAt, through: endedAt)` rounded to an Int (the kind filter is the function's own; the builder confirms and passes only heart-rate samples if it does not filter), then clear `activeSeenId` so one workout makes one summary. Any other status (abandoned, none) ends nothing. `public func dismissPending()` takes `pending` away. Function names avoid the append-only verbs (`note`, `dismissPending` are fine; no `set`/`clear`/`reset` names; checklist r, ac).
- D-3 Skip (state only, `WatchEffortRating.swift`): `public static let skipLabel = "Skip"` in `WatchEffortRatingCopy` (wrist-only copy, not in the contract file; the copy-parity tests compare title/scale/labels and must stay green); `private var skippedSessionIds: Set<String> = []`; `owedSessionIds` additionally filters `!skippedSessionIds.contains($0.sessionId)`; `public func skipPrompt()`: when a prompt is owed, insert `promptSessionId` into `skippedSessionIds`, forget the picked number and Crown carry exactly as `confirm()` does (`selected = nil; crownPosition = 0; crownCarry = 0`), `objectWillChange.send()`; records nothing, appends nothing (no row, no event). The header comment ("Once owed, the prompt has one way out: an answer") is rewritten: an answer, or Skip, which records nothing. The amended guard test in `WatchEffortRatingTests` (~l.839): the `banned` list loses `"skip"` and a new test pins that the ONLY skip-like name in the state and view files is `skipPrompt` / `skipLabel` (a scan for `skip` occurrences outside those two names fails), while `"dismiss"`, `"cancel"`, `"close"`, `"later"`, `"not now"` stay banned.

- S-9605 one test per gate: (a) completed but never seen active in this process (a `note(completed)` first, as after a relaunch) -> no pending; (b) completed with zero effort entries -> none; (c) `abandoned` -> none; (d) seen active, completed twice (`note` called again for the same completed row) -> pending unchanged, not rebuilt; (e) completed session of ANOTHER id than the one seen active -> none.
- S-9606 a new workout gives way: pending for A, then `note(active B)` -> pending nil; `note(active A-again)` is not possible (completed), covered by (d).
- S-9607 `dismissPending()` empties it; `objectWillChange` fires on build and on dismiss (observed through a Combine sink on the main queue with an `XCTestExpectation`, checklist v).
- S-9610 Skip: an owed prompt, `skipPrompt()`: `isPromptOwed` false, `owedSessionIds` empty, `selected == nil`, the store holds no new row (`store.readAll()` counts unchanged), and the session still has no effort rating (`engine.hasEffortRating(sid) == false`).

- S-9612 Skip keeps the first answer winning: skip, then `engine.recordEffortRating(4, sessionId:)` (an answer arriving from the phone) -> `hasEffortRating` true and nothing else changes; and a skipped prompt returns after `restore()` of a fresh state over the same store (the documented limit).
- S-9613 Skip with nothing owed does nothing (no crash, no change).
- S-9614 amended banned-words guard (see D-3): `skip` appears only as `skipPrompt` / `skipLabel`/`Skip` copy in the two files; `dismiss`, `cancel`, `close`, `later`, `not now` still fail the scan.
