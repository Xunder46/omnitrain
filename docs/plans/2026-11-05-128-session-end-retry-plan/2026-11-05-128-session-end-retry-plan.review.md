Fix candidates, smallest first: (a) give the ledger its own clock (a separate mirror parameter, or reuse the default `_utcNow` for the snapshot/lifecycle stamps) so the graph clock drives only `_armUnconfirmedEnd`/`takeOwedEnd` bounds — the 20 owed tests assert frame presence and states, never stamps, so they stay green while a fixed-clock graph regains strictly increasing `sentAt`; (b) make D-127 refuse what is not strictly newer — safer to avoid: it would also refuse a redelivered identical snapshot and it changes shipped semantics to repair a test fixture.
2. [Minor] `lib/state/watch/live_session_mirror_state.dart:795-812` (`takeOwedEnd`) and `:819-841` (`offerAllOwedEnds`) — the offer is counted, and on the third the entry retired, before the awaited `reportLifecycleFor` sends. A send that throws (production reports it, it does not crash: `lib/core/platform/watch_transport.dart:437-441,446-453`; the wiring reports link-offer throws, `watch_sync_wiring.dart:432-436`) consumes the offer without delivering it: on the third take the end is lost for good — `_retiredEnds` refuses re-arming and only a phone restart (D-3 row) can revive it, which for a wrist-only session with no repository row means never. In `offerAllOwedEnds` a first throw also abandons the remaining owed ends until the next link event or a wrist frame naming each one. Fix: count/retire on a returned `WatchDelivery` instead of before the send, or wrap the send in a try/catch that reports and restores the count.
3. [Minor] `lib/state/watch/live_session_mirror_state.dart:830` vs `:795-797` — a rewound clock: `takeOwedEnd` treats a future `since` (`age.isNegative`) as expired and retires, `offerAllOwedEnds` uses `.abs()`, so the same entry is retired by a wrist frame and re-offered by the link on the same run. Bounded either way (3 offers, the caps), but the two paths disagree about D-1 (iii) for one entry. Fix: drop `.abs()` to match `takeOwedEnd`.
4. [Minor] `lib/state/watch/watch_incoming_router.dart:204-232` — the row seam is read on every qualifying wrist frame: a `repository.getSession` (a store read) per `timer_state` tick, observation and receipt-like frame naming a session. For a session the mirror is actively holding this read can never change the answer (the row cannot be ended while the session runs; if the mirror holds an ended copy the ledger already arms the answer). Fix: skip the seam when `sessionId == _mirror.sessionId`; the restart case is unaffected (the restarted mirror holds the placeholder or a different id).
5. [Minor] `docs/watch_session_capture.md:321-323` — "the effort question is never owed for it (`WatchWorkoutSummaryTests`, S-12815 a and b)": neither test asserts the rating prompt. It is structurally true — prompts are appended only inside the wrist's own `end()` (`WatchEffortRating.swift:189-205`), which a phone-made `applyMessage` never runs — but no named test would fail if a prompt were appended for a phone-made end. Fix: extend `testS12815a` with a `prompts` assertion, or split the sentence and name the structural reason.

The known deviation is ratified, not new: D-1 (ii) retires the other owed ends only when the wrist announces an ENDED state for another session (`watch_incoming_router.dart:196-218`: `endedState` is read only from a lifecycle `state` or a snapshot `status`), because a plain frame naming session B does not prove the wrist left A — S-12806 needs two owed ends to coexist, and as built S-12811's second half confirms B's ended lifecycle retires A.
