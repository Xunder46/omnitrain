# Feature: 87b — the wrist says "New PR" when a set logged on the wrist beats the phone's best

> Status: BUILT 2026-10-27, awaiting review. Iteration 1 planned 2026-10-27 (seeded by the governor; planner expanded phases, added impact rows, edge scenarios D-15..D-19 and S-87b-17..24, and answered the research questions under Open questions). Series: `docs/plans/2026-10-26-87-wrist-new-pr-banner-index.md`. Depends on 87a (`bests_down` contract and phone sender, closed at `d0189d6d`). This is the PR the owner can see and feel.
> Next handoff: @developer (Phase 1 — Store)

## Goal and acceptance

87a puts each exercise's standing best on the wrist. 87b makes the wrist use it: when a set LOGGED ON THE WRIST beats the best, show a short "New PR" banner with a trophy and play one distinct tap instead of the normal "logged" tap.

Acceptance: (1) a wrist-logged strength set that strictly beats the best the wrist holds shows the banner for about 4 s, plays the PR tap and not the logged tap, and the VoiceOver reads it; (2) a wrist that never received a `bests_down` announces nothing; with one held, an exercise absent from it counts as first-ever; (3) the same set logged twice, or an equal set, never fires twice, including after the app is relaunched and while the phone has not yet taken the wrist's workout into its history; (4) a set logged on the phone and mirrored to the wrist never fires a wrist banner; (5) the feature stays light on the watch (D-9..D-13 below, each asserted by a test); (6) the Sync button's spinner waits for the bests like for any other reply.

## Owner decisions (2026-10-26 and 2026-10-27, final)

Look: banner + trophy + distinct tap, about 4 s, replaces the logged tap, never blocks Log, rest or Next. No data, no message. One banner per device: only sets logged on the wrist. No age limit on the wrist's copy of the bests (same as the phone, which never checks age). The wrist remembers its own finished sets until the phone has them, so it never celebrates the same set twice. The phone's toast is NOT changed. Constraint from the owner: nothing here may make the watch heavy on memory, work or battery.

## Decision Ledger

- D-1 PR rule, mirroring the phone's toast (`lib/features/session/workout_session_screen.dart:1042 _maybeShowPRToast`) and 87a's frame: only an effort of kind `set` with reps >= 1. If the set's `loadKg` > 0: weight axis, `e1rm = loadKg * (1 + reps/30)` (Epley, `StatsProgressService.epley1RM`), PR when `e1rm > bestE1rm`. Otherwise (no `loadKg`, zero, or negative): reps axis, PR when `reps > bestReps`. Strict `>`. A missing axis for the exercise is 0. Planner: read how the phone's watch importer maps a negative `loadKg` (band assist) into the entry's `weight` before the toast sees it, and report under Open questions if the wrist's axis choice for assisted sets would differ from the phone's (seeded default: mirror the toast, reps axis).
- D-2 Effective best = `max(held frame's best, the wrist's own best)` per axis. The own best is the best of the sets the wrist itself logged (this workout, and earlier ones the held frame may not contain yet). `max` is idempotent, so an own set the frame already counts changes nothing: no clearing logic is needed.
- D-3 No frame held means no verdict at all (no banner, no tap, no state change). A held frame with `bests: []` means every first set of an exercise is a PR (87a S-87a-3).
- D-4 Detection runs only inside the wrist's own log path (`WatchLoggingState.log`, `watch/watchos/Sources/WatchSessionEngine/WatchLoggingState.swift:908`), after the observation is stored. Sets that arrive from the phone (`session_snapshot`, `structure_change`) never reach it. It must not throw, delay or alter the log: any failure means no banner.
- D-5 The newest frame wins (latest `generatedAt`, a tie goes to the copy received later), the rule `WatchPhonePreferences.applyPreferencesDown` follows (`WatchPhonePreferences.swift:206`). A frame the validator refuses is refused whole: nothing stored, previous copy kept.
- D-6 Haptic: new `WatchHaptics.playPersonalRecord()`; a protocol extension default calls `playLogged()` so existing conformers compile (as `playFinished` does, `WatchLoggingModel.swift:262`). A PR log plays only the PR tap; any other log plays only the logged tap. `WristHaptics` picks a `WKHapticType` no other cue uses (taken: notification, stop, retry, click, success, directionUp, failure); one built-in type, no second delayed tap.
- D-7 Banner: trophy symbol plus "New PR", over the exercise screen, `allowsHitTesting(false)`, about 4 s, a second PR restarts the window. Expiry is read from the injected clock on the logging screen's EXISTING 1 s `poll()` (`WatchLoggingModel.swift:100`); no new `Timer`. Reduce Motion: no movement, opacity only. VoiceOver: the banner has a label and a one-time announcement per PR; text lives in `WatchSpokenText` (`WatchSpokenText.swift`) beside `duration` and `rating`.
- D-8 `bests_down` joins `WatchSyncProgressCopy.replyTypes` (`WatchSyncProgress.swift:31`), because the phone sends it last on every request: the spinner must not stop before it has landed. 87a deliberately left it out.
- D-9 COST: no new timer, no new radio traffic from the wrist, no background task. Detection is two dictionary lookups and one multiplication per logged set; no history is read or walked on the wrist.
- D-10 COST: the arriving frame is parsed into a dictionary ONCE, when it arrives, never per log.
- D-11 COST: a frame whose entries equal the held copy's writes nothing and parses nothing further. After any write settles, storage holds at most ONE `bests` row (older rows pruned in the same way `pruneExerciseBatches` prunes, `WatchSessionStore.swift:120`). The store is append-only, so without this a 300-entry row (about 20 to 30 KB) would be appended on every sync.
- D-12 COST: memory is at most 300 held entries plus one own-best entry per exercise the wrist logged. No per-set list is kept; the own bests are rebuilt on launch from the observations still in storage (unreceipted or not yet pruned), in one pass.
- D-13 COST: the wrist side adds no work to a sync that brings an unchanged frame beyond the equality check of D-11. The bytes the phone sends on every sync raise (the full frame, roughly 20 to 30 KB at the cap, an estimate not a measurement) are 87c's concern, not this PR's: this PR only states the size and does not change the wire.
- D-14 Out of scope: any change to the phone, to the contract, to the frame, to the phone's toast; showing bests on any screen; the Dart twin (`lib/watch/`) unless a parity test forces it (planner: read `docs/watch_session_sync.md` and the twin's store, report under Open questions); an age rule.
- D-15 (planner, 2026-10-27, vetoable) The own-best fold-in mirrors the phone toast's in-session throttle, not the phone's bests builder: every wrist-logged `set` with reps >= 1 updates the axis its verdict used (loadKg > 0 → e1rm axis; otherwise reps axis), whether or not the phone's builder would carry that set into a future frame. Evidence: the toast's reps path runs for `weight <= 0` and updates `_sessionRunningBestReps` (`workout_session_screen.dart:1075-1113`), so an assisted set updates the phone's throttle too; the phone's builder skipping assisted sets (`getAllTimeBests`, 87a phase 2) is about stored history, not about dedup. The own best is the dedup device (acceptance 3); the frame stays the phone's truth.
- D-16 (planner, 2026-10-27, vetoable) The own-best rebuild reads EVERY stored `set` observation with reps >= 1, confirmed or not, INCLUDING snapshot-applied phone entries. Snapshot entries are stored as plain observation records (recordId = the phone's entryId, no origin marker — `WatchSessionEngine.swift:958-992`), so there is no cheap way to exclude them, and excluding them would be wrong: a phone set the wrist holds is history the wrist knows, and a wrist log must not celebrate below it (snapshot bench 200 x 5 must silence a wrist 100 x 6). `max` is idempotent against the frame, so folding them in changes no verdict the frame already decides. This also closes the receipted-but-not-yet-in-bests relaunch window (acceptance 3). Derived reading of S-87b-8: that scenario's assertions are "no banner state and no tap" at arrival time; the fold-in of snapshot entries into the REBUILD is this planner's interpretation, offered for veto before Phase 2 hands off.
- D-17 (planner, 2026-10-27) `pruneBests`: after a write settles, storage holds at most ONE `bests` row; `pruneBests` drops every `bests` row whose `generatedAt` is older than the newest stored row (mirrors `pruneExerciseBatches`, `WatchSessionStore.swift:120`, `FileWatchSessionStore.swift:79`). The engine-contract guard S-004 pins the store's mutator surface to an explicit `allowed` set (`WatchSessionEngineTests.swift:329-335`): adding `pruneBests` REQUIRES adding it to that set in the same phase, or the suite goes red — that is the guard working, not a breakage.
- D-18 (planner, 2026-10-27, vetoable) `WristHaptics.playPersonalRecord` plays `WKHapticType.start` — no other cue in the repo uses it (taken: notification, stop, retry, click, success, directionUp, failure; `WatchLoggingView.swift:32`). One built-in type, no second delayed tap (D-6).
- D-19 (planner, 2026-10-27, vetoable) VoiceOver: the banner element carries `.accessibilityLabel`/`.accessibilityValue` (plan 84's pattern, watchOS 9-safe — `Package.swift` pins `.watchOS(.v9)`); the one-announcement-per-PR requirement of S-87b-14 is met by posting `AccessibilityNotification.Announcement` IF the compiler accepts it on watchOS 9 (no in-repo precedent — grep found zero `Announcement` uses in sources). If the API is unavailable on watchOS 9, the fallback is the label/value pair alone (VoiceOver reads the banner when it appears) and the implementer logs the substitution under Assumption Log; the governor's watch app build is the compiler check.

## Core scenarios (re-derive every number in the first run)

Fixture F (a held frame, kg): bench-press `e1rmKg` 116.6667 (from 100 x 5); push-up `repsBest` 12; squat absent.

- S-87b-1 Strict `>`: wrist logs bench-press 100 x 5 (e1rm 116.6667): not a PR. 100 x 6 (e1rm 120.0): PR. Red today: no detection exists.
- S-87b-2 No frame ever held: the same 100 x 6 gives no verdict, no banner, one logged tap. Frame with `bests: []`: the first set of any exercise is a PR.
- S-87b-3 Squat is absent from F: 60 x 5 (e1rm 70.0) is a PR (first-ever).
- S-87b-4 Bodyweight: push-up with no `loadKg`, 13 reps: PR (13 > 12); 12 reps: not a PR; a second 13 straight after: not a PR.
- S-87b-5 Repeat in one workout: bench 100 x 6 PR (120.0); another 100 x 6: not; then 100 x 7 (123.3333): PR.
- S-87b-6 Own set the phone does not have yet: workout A logs bench 100 x 6 (PR, observation stored, no receipt); the state is rebuilt as after a relaunch; workout B logs 100 x 6: not a PR even though F still says 116.6667. A later frame carrying bench 120.0 changes nothing for 100 x 6.
- S-87b-7 Only `set` efforts: a hold with extra load, a timed effort and a round never produce a verdict.
- S-87b-8 A phone-logged set arriving in a `session_snapshot` (bench 200 x 5) gives no banner state and no tap; the next wrist log still compares against F and the wrist's own sets only.
- S-87b-9 Taps (recording haptics): a PR log records one PR tap and zero logged taps; a non-PR log records zero PR taps and one logged tap; no log records neither.
- S-87b-10 Banner window with an injected clock: visible at t0 + 3.9 s, gone at t0 + 4.0 s; a PR at t0 + 2 s moves the end to t0 + 6 s; logging, resting and Next all work while it shows.
- S-87b-11 Storage: three frames with different entries leave one stored `bests` row, the one with the newest `generatedAt`; the same entries twice append once; an older `generatedAt` is ignored; a restore after relaunch returns the held copy.
- S-87b-12 Spinner: `bests_down` counts as a reply, so a sync whose last frame is `bests_down` ends two quiet seconds after it, not before.
- S-87b-13 A malformed frame (a fixture of 87a's invalid set) is refused whole: nothing stored, the previous copy still decides.
- S-87b-14 VoiceOver: the banner reads "New personal record" and one announcement is posted per PR, none for a non-PR log.
- S-87b-15 Units: the user's phone is in pounds; detection still compares kilograms from `loadKg`, the payload field (a 225 lb set is 102.0583 kg), and the banner shows no number.
- S-87b-16 Assisted set (loadKg -20, 8 reps, frame repsBest 6): reps axis, PR if the planner confirms D-1's default; else the confirmed phone behaviour.

Planner's edge scenarios (S-87b-17..24; numbering continues the seed's, gaps reserved for remediation):

- S-87b-17 Own-best rebuild covers receipted sets: bench 100 x 6 logged on the wrist, receipted by the phone (observation confirmed in storage — `pruneConfirmed` has no production caller, see Open questions d), state rebuilt as after a relaunch; logging 100 x 6 again is not a PR. Edge case of: S-87b-6.
- S-87b-18 Snapshot-applied phone set folds into the rebuild: a `session_snapshot` brings bench 200 x 5 (e1rm 233.3333); relaunch; the wrist logs 100 x 6 (e1rm 120.0): NOT a PR (120 < 233), even though F says 116.6667. Edge case of: S-87b-8. Vetoable per D-16.
- S-87b-19 `pruneBests` keeps the newest: storage holds `bests` rows with generatedAt 1000 and 2000; `pruneBests` leaves exactly the 2000 row. Edge case of: S-87b-11.
- S-87b-20 Store-contract guard updated: S-004's `allowed` set contains `pruneBests` and the module-wide mutation-verb scan still passes (the name contains "prune", not a banned verb). Edge case of: S-87b-11.
- S-87b-21 Recording haptics separation: a PR log records `personalRecords` 1 and `logged` 0; a non-PR log records 0 and 1; the model calls `playPersonalRecord()` INSTEAD of `playLogged()` on a PR (never both). Edge case of: S-87b-9.
- S-87b-22 App-target wiring source guard: `ios/OmniTrain Watch App/ContentView.swift` builds the holder beside `let preferences` (:23), passes it into the orchestrator's init (:155) and restores it in the restore path (:317 area); asserted by a NEW source-scan test reading that file via `Fixtures.repositoryRoot` (the pattern `WatchLoggedHapticTests.swift:205-212` already uses to read ContentView.swift under `swift test`). - S-87b-23 Assisted-set dedup: assisted set (loadKg -20, 8 reps) is a PR; a second identical assisted set straight after is not (the own best updated on the reps axis per D-15). Edge case of: S-87b-16.
