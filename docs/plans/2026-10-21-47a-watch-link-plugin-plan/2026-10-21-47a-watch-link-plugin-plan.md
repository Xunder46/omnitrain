## Goal and acceptance

| Situation on the phone | Now | After 47a |
|---|---|---|
| The watch queued a set and ended the workout while out of reach; the devices meet with the phone app closed | nothing arrives | the OS wakes the phone app, the plugin buffers the transfer until the app has attached its listener, the app imports it and sends the receipt |
| A frame arrives during a cold launch before the app's listener attaches | dropped | kept (bounded buffer) and delivered in order when the listener attaches |
| The phone sends a frame and the radio fails after the reachability check | counted as delivered | the send fails (or times out after 10 s) and the frame stays owed |
| The phone sends a receipt while the watch is out of reach | dropped | queued for the OS (`WatchDelivery.queued`) |
| The app asks whether the watch is reachable | read once at start, never updated | updated on every change |

## Decision Ledger

- D-1 Local plugin `packages/omnitrain_watch_link/`, iOS only, replaces the `watch_connectivity` dependency (pubspec path dependency; the lead edits `pubspec.yaml`, runs `flutter pub get` and `pod install`). Channels: `MethodChannel('omnitrain/watch_link/methods')`, `EventChannel('omnitrain/watch_link/events')`.
- D-2 Method contract. `status` -> map `{supported, paired, appInstalled, activated, reachable}` (booleans). `sendMessage(frame)` -> `WCSession.sendMessage(frame, replyHandler:, errorHandler:)`; the Flutter result completes (null) in the reply handler and fails with a `FlutterError` code `not_supported`, `not_activated`, `not_reachable` or `send_failed` otherwise, exactly one result per call. `transferUserInfo(frame)` -> `"queued"`, or `"already_queued"` when `outstandingUserInfoTransfers` holds a transfer whose `userInfo["messageId"]` equals the frame's `messageId` (a frame with no `messageId` is always queued); errors `not_supported`, `not_activated`.
- D-3 Event contract (one stream, every payload a map with `kind`): `{"kind":"message","frame":{...}}`, `{"kind":"userInfo","frame":{...}}`, `{"kind":"reachability","reachable":bool}`, `{"kind":"state", ...the status map}`. Native events are buffered while no Dart listener is attached (cap 500, oldest dropped past the cap) and flushed in order when `onListen` fires; events are emitted on the main thread. Delegate methods implemented: `activationDidCompleteWith` (emits state and reachability), `sessionDidBecomeInactive`, `sessionDidDeactivate` (re-activates), `sessionReachabilityDidChange`, `sessionWatchStateDidChange`, `didReceiveMessage` (no reply), `didReceiveMessage:replyHandler:` (replies `[:]` at once, so the sender's `sendMessage` completes), `didReceiveUserInfo`. Every event also logs one line `NSLog("OmniTrainWatchLink: <kind> <type or value>")` (frame `type` only, never contents) for the paired-simulator check.
- D-4 Dart API of the package (`lib/omnitrain_watch_link.dart` exports `watch_link.dart`, `watch_link_event.dart`): `class WatchLinkStatus {supported, paired, appInstalled, activated, reachable}` with `fromMap`; `sealed class WatchLinkEvent` with `WatchLinkMessage(frame)`, `WatchLinkUserInfo(frame)`, `WatchLinkReachability(reachable)`, `WatchLinkStateChanged(status)`; `class WatchLinkException implements Exception {code, message}`; `class WatchLink({MethodChannel? methods, EventChannel? events})` with `Future<WatchLinkStatus> status()`, `Future<void> sendMessage(Map<String, Object?> frame, {Duration timeout = const Duration(seconds: 10)})` (a platform error becomes `WatchLinkException(code)`, the timeout `WatchLinkException('timeout')`), `Future<String> transferUserInfo(Map<String, Object?> frame)`, `Stream<WatchLinkEvent> get events` (one broadcast stream over `receiveBroadcastStream`, created lazily, events decoded to the sealed types; an unknown `kind` is skipped).
- D-5 App side (`lib/core/platform/`), the one file that imports the package stays `watch_connectivity_channel.dart` (renamed class `WatchLinkChannel` in the same file name kept: `watch_connectivity_channel.dart`, so the plan 13 D-1 sentence stays true): `WatchMessageChannel` gains `Future<void> queue(Map<String, Object?> frame)`, `Stream<bool> get reachability` and `Future<WatchLinkInfo> get info` (new core value type `WatchLinkInfo {paired, appInstalled, reachable}` in `lib/core/platform/watch_link_info.dart`, so no plugin type escapes); `messages` carries both `WatchLinkMessage` and `WatchLinkUserInfo` frames. `WatchDelivery` gains `queued` (doc: handed to the OS queue; it arrives when the devices meet). `WatchConnectivityTransport`: `static bool isDurable(frame)` = `type == 'receipt'`; `send`: reachable -> `channel.send` (a thrown error: durable -> `queue` -> `queued`, else `undelivered` with the report as today), unreachable -> durable ? `queue` -> `queued` : `undelivered`; subscribes to `channel.reachability` inside `onIncoming`, right after the message subscription (listening is what makes the platform flush what it buffered, so the message listener must attach first or together with it; S-6817), and keeps `isPhoneReachable` current (and lowers it when a send fails); exposes `Stream<WatchLinkInfo> get linkChanges` (reachability or state changes, started by `refreshReachability`) and `Future<WatchLinkInfo> linkInfo()`; exposes `Stream<DateTime> get heard` (one event per inbound frame handed to the handler; the clock is injectable). The drop-before-handler rule stays; the native buffer is what keeps a cold-launch frame alive until the listener attaches.
- D-6 Out of scope: the status state and screen (47c), the wrist (47b), Android, any protocol change.
