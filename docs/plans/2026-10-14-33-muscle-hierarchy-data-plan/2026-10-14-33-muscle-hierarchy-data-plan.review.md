## Findings

1. [Major] `lib/data/repositories/hive_workout_repository.dart:536-546` — `_migrateMuscleLinkRoles` calls `_exerciseMuscleLinks(exerciseId)` OUTSIDE the `try`. A box row holding a map element with a `role` that is not `'primary'`/`'secondary'` throws `ArgumentError` inside `ExerciseMuscleLink.fromMap` (models.dart, unknown-role branch) before `normalize` is ever reached, and a map element with a non-String `muscle_group_id` throws a `TypeError` cast; neither is intercepted by `on ArgumentError`, so the step aborts, the version never advances, and the same row stops every later launch. The doc comment's guarantee ("a row whose links fail MuscleTaxonomy.normalize … throwing would stop the step") holds only for the normalize-poison classes; the brief's owner rule "a poisoned row cannot stop the step" is only half-proven. Not reachable through app writes (the box is only written with valid roles), so not a Blocker. The S-8 poisoned-row test (`test/data_migration_test.dart`, Hive group) stages only the secondary-only class, so the hole is unguarded. Fix: move the read inside the try and skip a row whose read fails (e.g. wrap read + normalize in one `try`/`catch (_) { continue; }`). Guard: an S-8 Hive test that puts `{'muscle_group_id': 'muscle-quads', 'role': 'tertiary'}` straight into box `exercise_muscle_groups` and asserts the step completes and the row is untouched. Related, same root: the reader (`:1706-1716`) also silently drops elements that are neither String nor Map — same observable outcome as the old `_asStringList`+`whereType` skip, so no regression; noted, no separate finding.
