2. [Major] `test/protein_consistency_signal_screen_test.dart:384-409` — `_seedWindowTarget`'s new today-row workaround is accurate but conceals a live production defect. The comment is correct: both `getNutritionTargetForDate` walks (`lib/data/repositories/mock_workout_repository.dart:1941-1950`, `lib/data/repositories/hive_workout_repository.dart:1130-1144`) step fixed 24-hour milliseconds over local-midnight keys, so on the day after a DST transition the walk lands at 01:00 local and never hits a midnight key — it returns null and the user's inherited target (Fuel adherence, protein signal, target screen) disappears for that day. A user in any DST locale hits this twice a year. Today's full run proves it live (2026-11-02 is the day after the US fall-back): `test/edge_case_test.dart:1002` (expected 2400, actual null), `test/protein_consistency_service_test.dart` "inherits the last stored target forward" (Mock and Hive), `test/state_test.dart` rollover ×2, `test/nutrition_test.dart` rollover, `test/edge_case_test.dart:628` streak. The screen test now passes on such a day only because the fixture writes today's row by hand. Fix: make both walks calendar-day arithmetic (`DateTime(y, m, d - 1)` — the same pattern `isSignalDismissed` in `lib/core/models/signals.dart` already uses), in Mock/Hive parity; then the today-row write can go. Guard: a repository test that saves a target at yesterday's midnight and reads today across a fixed DST boundary, on both harnesses. (The defect is pre-existing and outside this diff's files; the finding is that the diff's fixture hides it rather than exposing it.)
