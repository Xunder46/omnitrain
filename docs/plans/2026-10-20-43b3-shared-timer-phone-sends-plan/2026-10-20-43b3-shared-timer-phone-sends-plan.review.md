## Brief questions

1. **Spurious clear on a transient empty `inProgressWorkTimers()`** — see Minor 1. The success path is bridged: `loadSessionData` (`lib/state/workout/session_core_io.dart:131-194`) clears the timer managers at :147 and re-reads the same persisted stamps, and its final `_notify()` re-opens the debounce window, so the pass composes the same frame as `_delivered` and sends nothing. The reachable spurious clear is the failure path: a repository error inside the load leaves the managers empty while `hasActiveSession` stays true (`lib/state/workout/session_core.dart:135-138` reads only `currentSession`/`endedAtMs`/efforts), and the next pass sends `{kind: null}` for every delivered kind (`lib/state/watch/watch_timer_push.dart:151-153`), stopping the wrist's running timers. Self-heals at the next successful load (the cleared ledger re-offers the timers), but the wrist's clock is stopped until then.
2. **Mirror session id for a phone-started session** — the mirror's `sessionId` is set only when a wrist snapshot is folded in (the connect sequence's `requestSnapshot` answer, `lib/state/watch/live_session_mirror_state.dart:396-400`); until then, or while the mirror holds the placeholder or another session W, `_watchHoldsIt` returns false at `watch_timer_push.dart:127` and the echo guard is off. Harmless: a wrist timer started earlier is protected by the wrist's own earlier-start rule (43b1 D-4) when the frame arrives, and a frame naming a session the wrist is not running is refused by it. No finding.
3. **`startedAtMs` backdate** — yes: `startTimedEntry` sets `startedAtMs: now - offsetMs` when the entry had a preset target (`lib/state/workout/timer_manager.dart:642-647`), so the wire `startedAt` is earlier than the real start. For a same-slot timer the wrist holds from a real earlier start this can make the phone's artificial instant earlier, so the earlier-start arm of `_watchHoldsIt` (`watch_timer_push.dart:190-193`) does not skip and the phone's frame goes out; the wrist's earlier-start-wins then adopts the backdated instant and the wrist's clock jumps. Reachable only while 43b2's adoption has not reached the phone — in the adopted case `startTimedEntry` is an invalid transition and returns (`timer_manager.dart:634-636`). The outcome is phone and wrist agreeing on the phone's backdated clock, so Nit 1 (a limits line), not a code change.
4. **Two efforts of the same wire kind** — reachable: the in-progress lock (`_getAnotherInProgressKey`, `lib/features/session/workout_session_timer_mixin.dart:62-68`, enforced at :562 and :644) lives in the screen's state, so it is lost when the session screen is rebuilt while `TimerManager`'s instances stay active. The clear logic is right: delivered A vs wanted B with a different `startedAt` produces `clears[kind] = null` and `next[kind] = B` (`watch_timer_push.dart:144-149`) — two frames, the D-2b shape; an older timer that was never delivered needs no clear and gets none. A same-millisecond tie across two efforts would skip the clear frame (`watch_timer_push.dart:146`) and send B while the wrist still holds A — unreachable in practice (distinct `DateTime.now()` calls; S-6217's fixture even waits one out) and the wrist's slot rule backstops. No finding.
5. **Docs claims** — checked against the code and the test files: `docs/state_management/workout_state.md:222-230`, `docs/state_management/watch_surface.md:222-228` and `docs/watch_session_capture.md:287-307` name only files, types, groups and tests that exist (`WatchTimerPush`, `WatchSyncGraph.timerPush` at `watch_sync_wiring.dart:99,271,304`, the bind line at `lib/main.dart:399`, `sendTimers` at `live_session_mirror_state.dart:386-389`, the 9 + 14 named tests). The limits are stated correctly, including "a wrist-started timer does not yet run on the phone (plan 43b2)" — true, 43b2 is not built (its plan status: "SEEDED (2026-10-20), not built"; no phone-side timer adoption exists in `lib/`). No 43b2/43c behaviour is claimed as delivered. One consequence is Major 1.

Fix (smallest): in `_pushOnce`, do not compose clears from a pass whose state is mid-reload — e.g. skip the pass while `state.isLoading`, or have `loadSessionData`'s catch re-raise the managers' last known state. No code change requested.
4. **[Nit] `lib/state/watch/live_session_mirror_state.dart:386-389`** — `sendTimers`, unlike `sendRatingFor` (:364-366), does not answer `undelivered` when the mirror holds another session; the frame is attempted and refused by the wrist.
