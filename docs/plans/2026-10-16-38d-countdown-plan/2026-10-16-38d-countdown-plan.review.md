## Findings
1. [MINOR] `lib/state/workout/timer_manager.dart:376-377` — the doc comment "The round at [fromIndex] is skipped when it is already finished; a round that is running or paused keeps the length it started with" reads two ways: as a rule about later rounds (true — the `else if` branch) or as a rule that also protects a running/paused round *at* `fromIndex` (false — the code rewrites it; only `finished` is skipped there). A maintainer (38e reuses the round-length control) calling the method directly for a running round would silently change its length while believing the comment promised otherwise. No live path reaches that call today (the row is locked mid-round), so behaviour is correct. Fix: reword to "a *later* round that is running or paused keeps the length it started with". Check: read the comment against `state_test.dart:2563` (`updatePlannedDurationFrom(effortId, 0, 300)` with round 1 running → touched `[0, 2]`, round 1 keeps 180) — the test already pins the real rule; no new test needed.
