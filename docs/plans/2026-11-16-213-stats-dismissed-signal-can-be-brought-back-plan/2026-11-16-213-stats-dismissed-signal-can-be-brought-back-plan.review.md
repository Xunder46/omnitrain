## Answers to the brief's five questions
1. **Undo semantics — OK.** The map is read at undo time: `signalDismissalsWithout(_signalsDismissedAtMs, id)` (stats_screen.dart:309) against whatever the field holds now. After a completed silent reload, the field was reassigned from a store read that awaits the tail first (stats_screen.dart:190-197, 237), so the snapshot includes the dismissal and Undo removes it correctly; a card that is no longer a candidate cannot be restored, because the view re-resolves the held (post-reload) candidates. The only imperfect interleaving is Finding 2 (view-only). The unmounted path is safe: assigning a field on a disposed State needs no widget, `mounted` gates the `setState` (stats_screen.dart:311-323), and `_signalsService == null` (no load, hence no possible dismissal) returns early. S-21395 pins the post-pop write.
2. **Message outlives the screen — acceptable, as the plan documents.** The messenger is app-level, so the bar can show over another screen for 6 s; tapping `Undo` there runs `_undoDismissal` on the disposed State — no `context` use, field assignment plus the chained write through the captured service (stats_screen.dart:306-328) — which is exactly S-21395. `clearSnackBars()` in `_dismissSignal` clears any app-level bar showing at that moment (e.g. a "Routine saved successfully" message shown seconds earlier on another screen); at the moment of a dismiss tap Stats itself shows no other message (grep: stats_screen.dart has only the new one) and inherits none, so nothing on-screen is lost; the cleared bar is a transient info message, and the plan's Input-reality 7 records the choice. PRToast bars are session-scoped and never co-visible.
3. **`persist` on OmniMessage — OK.** Null keeps Flutter's default (`persist` defaults to `action != null`), so every other caller is unchanged; `grep 'action: SnackBarAction' lib` matches only stats_screen.dart:292, and no caller builds a `SnackBarAction` elsewhere, so Stats is the only caller with an action. The `ui_standards_contract_test` S-2702 rule still holds: the diff builds no raw `SnackBar` outside `omni_message.dart` (which the scan excepts), adds no allowlist entry and raises no ratchet. Callers passing no action (seen in grep, all without `action:`): workout_session_timer_mixin.dart:646,728, session_summary_screen.dart:508, profile_screen.dart:789, food_form.dart:395, exercise_library_detail_screen.dart:102, settings_screen.dart:1061 (`showOn`), routine_setup_screen.dart:958,965,995.
