## Brief questions
1. No double tap, no skip in any reachable interleaving: both loops run on the main actor and `step()` is synchronous, so `arm()`'s cancel-then-restart can never overlap a `step()`; the shared `WatchRestPing` (WatchRestPingScheduler.swift:23, WatchRestPing.swift:47-58) dedupes per rest row, so a re-arm's first `step()` re-asks and stays silent, and a boundary crossed while nobody looked is caught by the next arm's first `step()` (one tap for the gap). A cancelled loop resumes from its sleep, sees `Task.isCancelled`, and exits before its next `step()`. The one skip window is finding 3 (the two clock reads inside `step()`).
2. The skip is sound against overlapping requests and the ms truncation is exact end to end: the stamp is truncated to whole ms (watch_sync_request_handler.dart:135-141), `utcIso` then prints 3 fractional digits (wire_timestamps.dart:12-15), the wrist parses with `ISO8601DateFormatter(.withFractionalSeconds)` (WatchRecords.swift:151-171) into `catalog.generatedAt` (WatchRoutineRecords.swift:317), `paths.syncedAt` returns it unchanged (WatchStartPaths.swift:345), the bridge re-serialises with the same 3-digit formatter (WatchConnectivityBridge.swift:72), and `sinceOf` parses back to the same millisecond instant — `since == stamp` compares equal, correctly. A backwards clock changes nothing: the wrist's own drop rule (`sent.generatedAt < catalog.generatedAt`, WatchStartPaths.swift:~420) would discard older-stamped frames anyway, so the skip matches the pre-62 outcome. The one real hole is the probe/stamped rebuild window — finding 2.
