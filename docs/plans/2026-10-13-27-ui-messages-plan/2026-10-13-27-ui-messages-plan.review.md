# Plan 29 · unsaved-work guards, delete confirmations
## Findings
5. [Blocker] lib/features/nutrition/add_food_screen.dart (`_FoodFormProbe`, ~226-340) + lib/features/nutrition/widgets/food_form.dart:410 — New Food photo loss. The probe detects dirty only through rendered `FormField` values and `EditableText` controllers; the photo tile is neither. `_NewFoodFormScreen` hosts `FoodForm` with `initial: null` and no `onImageSave`, and `handlePickedImage` returns early in create mode, so a picked photo is form-local, never persisted, and does not mark the form dirty: pick photo → back → pops with no dialog → the photo choice is silently lost. Violates the plan's goal "no way to lose data without the dialog" and D-29.2 ("for create screens, any field non-empty/non-default"). The same exclusion is correct for the legacy edit shim, which wires `onImageSave` so photos persist immediately. Fix: a `FoodForm` change hook (e.g. `onImageChanged`) that the New Food host marks dirty from. Guard: a New Food guard test that picks a photo via the `handlePickedImage` seam, then `handlePopRoute`, and expects the dialog.
6. [Minor] docs/my_routines.md:230 — the empty-state sentence still reads "Circle icon + 'No Routines Yet' + 'Create your first routine' message"; the screen now renders `OmniEmptyState` and the hint is "Create your first routine to get started" (screen_widget_test.dart:1045). Fix: one-line doc update.

Conforming: all four guard sites route through `ConfirmationDialog.showUnsavedChanges` (create_period_screen.dart:307, nutrition_target_screen.dart:114, add_food_screen.dart:407/938); `_submit` in create_period_screen.dart:356-431 pops only on success and surfaces inline errors otherwise; dirty detection covers name/notes/dates/colour/focus-modalities against initState baselines, and retyping the stored value is not dirty (tested); Cancel returns before any state change (`_busy` is set only after confirm) for both `food-remove-*` and `category-delete-*` dialogs; `_DeleteGroupDialog` buttons carry the utility shape; Edit Food (auto-save) is untouched, as the plan's named exception.
